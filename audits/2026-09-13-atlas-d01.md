# Écart D01 entre les échanges et FLOW Atlas

Audit local du 13 septembre 2026, à la suite de U115 puis du choix U116.

## Diagnostic

Les réponses HTTP `/api/model?space=backlog` et `/api/model?space=release` reproduisaient les nœuds JSON de leurs espaces respectifs. Le lecteur n’utilisait pas un ancien cache ou un modèle Markdown. Les nœuds de D01 conservaient les six capacités de P81 dans les deux espaces. P82, avec les cinq libellés plus récents, figurait uniquement dans `alternatives` du backlog ; l’interface ne rendait pas cette collection.

La migration avait conservé l’ancienne décomposition faute d’adoption explicite de sa fusion. Une réponse présentant P82 comme le modèle courant aurait donc contredit le JSON. Le choix d’une proposition comme base de réflexion ne doit pas être confondu avec sa validation métier.

| État antérieur | Backlog courant | Conservation |
| --- | --- | --- |

| D02.c — Reservation | Inchangé | Validation du nom et réexamen du rattachement conservés. |

Le backlog 2026-09-13.3 contient 35 capacités, dont cinq dans D01. La release pointée reste 2026-09-13.2 avec 36 capacités, dont six dans D01. Les fichiers de release, décisions et preuves figées restent inchangés. Aucun autre domaine n’est redécoupé. La comparaison de publication reprend les 47 décisions compatibles et ne crée aucune validation supplémentaire.

P82 ne figure plus parmi les alternatives distinctes du backlog : elle est intégrée à ses nœuds courants. P84 reste une proposition séparée pour D04 et devient visible dans Atlas, avec ses sources, sans remplacement automatique. Les données affichées proviennent toujours uniquement du JSON de l’espace sélectionné.

## Appuis de marché et limites

Les appuis déjà examinés pour P82 sont conservés : ELM068/ELM075/ELM076 et CMP040/CMP042/CMP045, décrits dans les registres de marché et la proposition P82. Le regroupement D01.e est local ; aucun rang SAP ou Microsoft ni nouvelle équivalence n’est affirmé. Les correspondances des anciennes D01.a/b éclairent désormais D01.e ; leur regroupement reste à éprouver. Cette correction d’intégration ne réalise pas de nouvelle vérification externe.

## Vérification

Contrôler la liste exacte des cinq noms dans le backlog via JSON, API et navigateur, la conservation des six noms publiés en release, la recherche et le rechargement d’Inventory Tracking, les sources et la visibilité de P84 exclusivement dans le backlog. Les tests du modèle, de publication et de navigation vérifient la structure et les validations ; aucun test ne vaut validation des frontières métier.
